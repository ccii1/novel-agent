# Agent 审核与流程评估

## 业务职责

规划、正文写作、正文审核和记忆处理具有不同的输入和状态修改范围。正文审核在生成之后执行；记忆审核在记忆提取之后执行，防止摘要和事实改变原文含义。人物、剧情、节奏和文风都读取同一章正文，可以由一次调用按四个维度完成检查。保留输出字段校验与程序统计，四个维度需要分别给出结论，问题标明所属维度。

记忆修正由 `MemoryExtractionAgent` 的 `MEMORY_REPAIR` 任务完成。任务只接收当前正文、历史记忆、待审核增量、审核意见和人工要求，输出完整记忆增量。独立的 `MemoryCheckAgent` 继续检查修正结果。每次自动修正最多三轮，费用、任务、模型响应、证据和结果均持久化。人工处理可以确认建议或编辑记忆，不要求修改大纲。

## 比较方式

`NOVEL_REVIEW_MODE=combined` 使用联合审核；`parallel` 使用四项并行审核。正常章节分别需要4次和7次调用，阶段规划、正文修改与记忆修正另计。两种模式使用相同正文证据规则、程序字数与对话统计、节奏记录和重要变更审批。

默认使用 `parallel`。本次使用段落引用的同章、同模型对照中，联合审核输入27,452 token，四项合计61,555 token，输入减少约55%；联合审核执行15.6秒，四项并行阶段14.1秒。两种模式的本次报告均通过。独立库使用相同正文与设定，未复制正式作品的全部历史记忆，报告用于评估审核方式，不直接作为修改正式作品的依据。全部调用使用免费本地服务，实际费用均为0元。

真实记忆修正验证使用已经保存的第二章、待审核记忆和审核意见。在独立数据库执行两轮模型修正与复审后，记忆版本更新为1，并创建下一章任务；正文和大纲保持原样。审核与提取通过段落、字段路径读取实际证据，避免依赖模型重新抄写引文。真实调用与任务结果保存在忽略目录 `.work/memory-repair-live-result.json`。

`LiveReviewComparisonTest` 在独立数据库中读取已经保存的同一章正文和设定，固定免费本地模型 `gpt-5.6-terra`，执行一次联合审核与四项并行审核。记录每次真实输入、输出、缓存用量、模型耗时、并行阶段总耗时和报告；不会生成或修改用户作品。运行前核对服务已配置且计费方式为 `unmetered`。结果保存在忽略目录 `.work/review-comparison-results.json`。

比较时同时观察审核问题和人工评价。单章、单次、同一个模型的结果只能说明本次调用的成本与等待时间，无法证明联合审核与独立审核的质量相同。验证阅读效果需要覆盖不同篇幅、人物数量、时间线冲突、推断误写为事实、伏笔遗漏等有人工标注的章节，并评估问题召回率、误报率和每个有效问题的费用。
