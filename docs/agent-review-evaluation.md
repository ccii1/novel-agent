# Agent 审核与流程评估

当前编排版本：1.19.0；核查日期：2026-10-25。完整执行流程见 [小说 Agent 流程与职责](multi-agent-workflow.md)。

## 业务职责

规划、正文写作、正文审核和记忆处理具有不同的输入和状态修改范围。正文审核在生成之后执行；记忆审核在记忆提取之后执行，防止摘要和事实改变原文含义。人物、剧情、节奏和文风都读取同一章正文，可以由一次调用按四个维度完成检查。保留输出字段校验与程序统计，四个维度需要分别给出结论，问题标明所属维度。

记忆修正由 `MemoryExtractionAgent` 的 `MEMORY_REPAIR` 任务完成。任务只接收当前正文、历史记忆、待审核增量、审核意见和人工要求，输出完整记忆增量。独立的 `MemoryCheckAgent` 继续检查修正结果。每次自动修正最多三轮，费用、任务、模型响应、证据和结果均持久化。人工处理可以确认建议或编辑记忆，不要求修改大纲。

## 已有记录

2026-10-18 读取本机作品的持久化观测记录：四项正文检查各有8次调用。

| 检查 | 平均输入 token | 平均模型耗时 |
| --- | ---: | ---: |
| 人物 | 15,964 | 7.7秒 |
| 剧情 | 15,843 | 8.4秒 |
| 节奏 | 17,875 | 14.8秒 |
| 文风 | 16,372 | 17.6秒 |

每轮合计约66,054个输入 token。四项任务并行运行，每轮总等待时间受最慢任务与排队影响，不能将四项平均耗时直接相加。记忆提取8次调用的平均模型耗时约35.5秒，记忆审核5次调用平均约21.3秒；写作、重写和记忆提取仍占较多时间，合并正文检查无法消除这些调用。

## 比较方式

默认 `NOVEL_REVIEW_MODE=combined`，同一次综合审核分别输出人物、剧情、节奏、文风结论，问题带 `dimension` 与原文证据。单组记忆且全部一次通过时，每章包含4次主要调用；工具查询、记忆分组、正文修改、上下文压缩和 HTTP 重试按实际次数记录。审核报告直接生成修改要求，写作组件复用 `REWRITE` 操作。

已保存的单章同模型对照记录中，联合审核输入27,452 token，四项合计61,555 token，输入减少约55%；联合审核执行15.6秒，四项并行阶段14.1秒。两种模式的报告均通过。该记录早于1.19.0，独立库使用相同正文与设定，未复制正式作品的全部历史记忆；全部调用使用免费本地服务，费用为0元，结果仅说明对应样本的表现。

真实记忆修正验证使用已经保存的第二章、待审核记忆和审核意见。在独立数据库执行两轮模型修正与复审后，记忆版本更新为1，并创建下一章任务；正文和大纲保持原样。审核与提取通过段落、字段路径读取实际证据，避免依赖模型重新抄写引文。真实调用与任务结果保存在忽略目录 `.work/memory-repair-live-result.json`。

`LiveReviewComparisonTest` 在独立数据库中读取已经保存的同一章正文和设定，固定免费本地模型 `gpt-5.6-terra`，执行一次联合审核与四项并行审核。记录每次真实输入、输出、缓存用量、模型耗时、并行阶段总耗时和报告；不会生成或修改用户作品。运行前核对服务已配置且计费方式为 `unmetered`。结果保存在忽略目录 `.work/review-comparison-results.json`。

比较时同时观察审核问题和人工评价。单章、单次、同一个模型的结果只能说明本次调用的成本与等待时间，无法证明联合审核与独立审核的质量相同。验证阅读效果需要覆盖不同篇幅、人物数量、时间线冲突、推断误写为事实、伏笔遗漏等有人工标注的章节，并评估问题召回率、误报率和每个有效问题的费用。

## 当前版本验证范围

1.19.0 已通过前端构建、后端编译和打包；按用户安排暂停测试执行。后续验证需要同时记录审核质量、压缩前后大小、是否保留关键规则与原文来源、完成所需请求次数，以及供应商返回的缓存 token。稳定前缀指纹用于确认请求复用条件，缓存命中率使用实际返回数据计算，缺失值保留未知。
